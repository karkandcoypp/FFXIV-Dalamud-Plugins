# Проверка VendorProfit 0.1.0.0

## 0.3.0 — внешний сканер

Пакет дополнен отдельным Python-скриптом, обращающимся только к Universalis; плагин экспортирует каталог и читает локальный результат. Во внешнем режиме отсутствует fallback к встроенному таймеру, заявки дедуплицируются независимо от времени загрузки книги, покупки ограничены конкретными внешними listing ID. Показатели денежных лимитов и журнал не сбрасываются.

Проверены 87 проверок ядра и 8 Python-проверок скрипта: налоги, ROI, неправильный сервер, устаревшая/будущая книга, неверные ID/количества, частичный отказ, cooldown, атомарная запись, отсутствие игровых зависимостей, повторный неизменившийся билет, обновление даты без изменения цены и отсутствие подмены целевого лота другим. Самостоятельный `--once` выполнен по одному предмету на Cerberus: один публичный HTTPS-запрос, 0 ошибок, 0 неизвестных книг, подходящих лотов не найдено. К игре не обращались; запуск из нового UI и реальные покупки новой версии не проверены.

## 0.2.0 — периодический поиск и автопокупка

Автопокупка по умолчанию выключена, пробный режим включён. Новое ядро покрыто модельными проверками через fake gateway: лимиты полной цены/бюджета/ROI/количества, другой персонаж/сервер, закрытый аукцион, полный инвентарь, повтор listing ID, свежая убыточная цена, журнал до отправки, отказ запроса/отправки, ожидание одного ответа, повторный запрос перед следующим стаком и требование совпадения списания гилей с приростом предметов. Полная проверка: 81 тест, 0 отказов. Игровые запросы вынесены в Framework-поток. Код нативного пути скомпилирован с API 15; настоящие покупки и новые нативные запросы в клиенте при разработке не выполнялись, гили не тратились. Публичный выпуск проходит обычный workflow; проверка в игре начинается с пробного режима.

- Сборка Release, Dalamud API 15 / .NET 10: 0 ошибок, 0 предупреждений (`--warnaserror`).
- 31 локальная проверка: арифметика полных стаков и налога на примерах пользователя, HQ, неверные и неполные данные, временные метки, сопоставление строк после сортировки/переработки, неоднозначные NQ/HQ, 429 и частичный отказ пакета.
- 3 ограниченные живые HTTP-проверки через **тот же C# MarketClient**, без игры и покупок: `aggregated/80/8144`, `80/8144?listings=3&entries=0`, `80/8144,8142?listings=3&entries=0`. Все прошли. Изолированная среда не разрешала DNS; проверка выполнена с сетевым доступом вне sandbox.
- 2 проверки нового выпуска: сохранение других записей ленты / правильный тег; отсутствие вызовов покупки и записи в игровые UI-узлы.
- 8 общих проверок публикации прошли. Для тестов временных локальных Git-репозиториев потребовалось исполнение вне sandbox из-за запрета MSYS.
- ZIP, CRC, DLL, манифест, API и соглашение версии/тега проверены общим `tools/verify_release.py`. SHA256 находится в `artifacts/VendorProfit.zip.sha256`.
- Проверка упаковки выполнялась с временным каталогом в рабочей папке, поскольку sandbox блокировал создание файлов в назначенном системном Temp.

Не проверены: загрузка DLL в запущенном клиенте FFXIV, реальное совпадение/позиция рамок при разных масштабах и форматах UI, прокрутка, сортировка, покупка одного пробного стака и фактическая продажа NPC. Полный производственный проход фонового каталога новым C# клиентом не запускался; проверены его ограниченные запросы и поведение на модельном частичном отказе.

Публичный ZIP скачан и проверен: CRC, манифест/API, версия DLL `0.1.0.0`, SHA256 `bbe599a64d0450c853712591ad5345fb94d0c889c0f9860b056df01d22151c26` совпадает с опубликованным sidecar. В канонической ленте появилась запись VendorProfit; остальные пять записей идентичны предыдущим. Личные настройки и изменения CraftProfile не входят в этот выпуск.


## 0.1.1

В текущем клиенте воспроизведена ошибка 0.1.0: после открытия Clear Demimateria II штатные строки заполнены, но плагин остаётся в ожидании. Сетевые покупки при проверке не выполнялись. В новой версии убраны зависимости от флагов ожидания/обновления и сетевого подтверждения всех лотов; проверяются конкретные отображённые денежные значения против нативной книги и заголовка. Показатели ограничены видимыми строками.

Добавлены регрессии на разбор колонок, совпадение с нативной книгой, смену предмета, расхождение налога, лишние числовые поля, неоднозначный HQ/NQ и ограничение быстрого режима: 100 предметов, пять запросов книг, ноль агрегатов. 41 локальная и четыре живые HTTP-проверки прошли; ограниченный быстрый запрос Cerberus занял 0,36 секунды (один предмет, не прогноз времени всего списка). Сборка Release без предупреждений и проверка упаковки прошли. Новая отрисовка ещё требует подтверждения в игре после обновления.


## 0.1.2

Добавлен ручной быстрый проход всех серверов Chaos с получением состава дата-центра и имён миров из Universalis. Таблица и кэш сохраняют мир каждого лота. Проверены модельные сценарии всех восьми серверов, отказ одного сервера с сохранением остальных, неверный worldID в ответе, остановка на длительном cooldown и совместимость старого кэша. 49 локальных проверок прошли. Живой ограниченный проход `--chaos-live` по одному предмету на каждом сервере прошёл (два дополнительных утверждения, всего 51): восемь миров, ноль отказов запросов; четыре книги исключены как неизвестные/несвежие; подходящих лотов в этой пробе не найдено. Этот тест не подтверждает поведение нового UI в игре. Полный каталог автоматически не расширяется.


## 0.4.0 — фоновые уведомления

Фоновый импорт/поиск работает без открытого аукциона; локальные сообщения выводятся через IChatGui.Print (Echo), без сетевых команд чата. Модельные проверки покрывают пороги, сервер/Chaos, свежесть, корректность сумм, новые ID, повтор ID при изменении цены и восстановленную историю. Скрипт проверен на Chaos, частичный отказ и распространение долгого Retry-After. Автоматические игровые покупки и доставка сообщения в живом клиенте при разработке не проверялись; отправок другим игрокам не было.

## 0.5.0 — упрощение интерфейса

Содержимое разделено на четыре вкладки; обработчики поиска, сохранения настроек, ограничения покупок и журнал расходов сохранены. Конструктор плагина и игровые сервисы на визуальном стенде не запускаются. Проверена фактическая отрисовка всех четырёх вкладок при 850×520 / шрифт 16 и 1100×720 / шрифт 21,6; PNG просмотрены. Поля ввода на стенде инертные, поскольку нативное расширение ввода требует окружения Dalamud. Это проверка компоновки, а не ввода, запуска процессов или покупок. После установки остаётся проверить клики, ввод, подсветку и масштаб в живом клиенте. Настоящие покупки и сообщения в чат при разработке не отправлялись.

Локально: сборка API 15 без предупреждений, 96 C# проверок, 11 тестов worker, два теста упаковки/ленты и восемь отрисовок UI прошли. Установочный ZIP проверен общим verify_release.py.

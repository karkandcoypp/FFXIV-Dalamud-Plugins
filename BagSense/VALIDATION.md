The installed-data catalog contained 6,743 items with regular merchant listings, 3,404 recipe ingredients, and 3,385 direct exchange inputs. These are metadata coverage counts, not claims that every route or character access condition is resolved. The final catalog check completed in approximately 200 ms on this machine.

## UI evidence

The harness calls `BagWindow.Draw` in a standalone native ImGui context with isolated demo items and goals. Scenarios cover English and Russian, inventory/goals/plan, 860×570, 1120×760 and 1440×1000 with scale 1.35. PNGs were generated and inventory, goals, plan and enlarged/minimum layouts were visually inspected. Scrollable item details are intentional.

Text and number entry fields are rendered as inert stand-ins: the Dalamud InputText extension needs the game-host text input environment. The harness does not test typing, clicks, the game's icon service or clipboard integration. Sample icons are intentionally empty. Standalone font rasterization can differ from the game's renderer.

## Still needs in-game verification

1. Add the built DLL under Dev Plugin Locations, enable BagSense, and open `/bagsense`.
2. Confirm loaded bag/Armoury quantities, equipped-item protection and saved gearset protection against the character's actual items.
3. Enter an item note, create a goal and add the same item to a second goal. Check the summed reserve. Complete a goal and verify that its reservation is released.
4. Add an eligible item to the cleanup plan. Change its quantity manually; the plan should require review, rather than silently claim completion.
5. Reload the plugin and confirm notes/goals/plan persist. Log out and change characters; the other character should have independent data.
6. Open an inventory item's context menu and select BagSense. Check RU/EN switching, text entry, item icons and clipboard export.

These interactions have not been performed inside FFXIV for this build. Publication does not constitute in-game verification. The initial local validation did not inject a plugin into the game; the subsequent release is built and published through `bagsense-release.yml`.

## Build environment notes

NuGet's online vulnerability endpoint was unavailable in the restricted environment. The local build used cached packages and the explicit `-Offline` switch, which disables that online audit for the invocation. Compiler warnings remain errors. Standard DalamudPackager encountered a temporary-file access restriction; the provided build script creates and validates the two-file package directly using .NET ZIP APIs. Release builds on GitHub retain the online audit and additionally check the shared index updater and package metadata.
